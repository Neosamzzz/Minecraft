# FTB 熟人服公共团队代码方案

记录日期：2026-11-01。
关联：[Issue #7：梳理并配置好游戏内的 FTB 相关功能](https://github.com/Neosamzzz/Minecraft/issues/7)。
状态：已记录讨论结论，尚未修改代码或部署。本文件不是实现完成或游戏验收记录。

## 目标与已确定方向

服务器供熟人朋友一起玩，大家共同推进任务，不要求玩家自行建队、邀请、加入或管理团队。重点是简化共同游玩的规则，不是只改界面名称。

- 全服使用同一个固定公共团队，玩家进服自动加入，新玩家直接接续已有任务进度。
- 任务进度全服共享；普通奖励按每名玩家分别领取，避免只能由一个人领取。
- 普通玩家不需要建队、邀请、退队、换队；服务端规则应保证公共团队关系，不能仅靠隐藏按钮。
- 收起不再需要的团队操作入口；服主保留必要的管理与任务编辑能力。
- 保留已有进度，不直接清空或用新建空队伍替换已有团队数据。
- 复用现有 FTB 团队与任务系统，控制修改范围，不另外开发复杂的团队系统。

## 最小版本与后续顺序

第一步实现固定公共团队、自动归队、共享任务进度及个人领奖。多余界面的精简可以随后处理，不作为先验证共同游玩的前置条件。

实现前需核实服务端现有团队及任务数据，决定复用哪个团队。如果已有多个团队的有效进度，需要另行确定迁移办法，不能假定自动归队会合并进度。

现有任务可能有独立奖励配置。实现时需核实个人领取的实际行为及可重复任务等例外，不能仅凭默认值承诺所有奖励都按同一方式发放。

## 当前依据与边界

本轮只读调查确认，本机实例安装 FTB Library 5.4.7.2、FTB Quests 1202.9.0、Item Filters 1.0.4.2，未发现 FTB Utilities。Library 的 JAR 文件名标为 5.4.7.0，但内部元数据和启动日志为 5.4.7.2。

本机最近一次已检查的启动日志记录 0 章节、0 任务、0 条件、0 奖励；本机存档已有单人团队及任务数据。上述结果不代表远程服务器状态，远程服务器尚未核实。

团队与公共界面主要由 FTB Library 提供，仓库当前包含的是 FTB Quests 源码。具体修改位置、接入方式及兼容性尚未验证；目前不能断言只修改某一个模组即可覆盖全部行为。

补充源码依据：`ServerQuestFile.getData(UUID)` 通过 `FTBLibAPI.getTeamID` 查找玩家团队，`ServerQuestData` 将任务进度和领奖记录保存到该团队的数据文件。因此同队共享进度已有基础，固定团队与自动归队仍需接入 Library 的团队规则；当前源码没有实现本方案的全服自动归队。

`Reward.isTeamReward()` 对可重复任务直接返回 true；普通任务才使用单项 `team_reward` 或全局 `default_reward_team`。因此个人领奖约定适用于普通奖励，不能直接推广到可重复任务。团队删除事件还会删除对应任务数据，迁移时应保留原队数据。数据与源码入口见 [FTB 开发说明](../FTB-Quests/DEVELOPMENT.md#任务功能与数据位置)。

## 最低验收范围

- 两名玩家自动进入同一团队，其中一人完成任务后双方进度同步。
- 普通奖励两人各可领取一次，不重复发放；核实已有奖励配置及特殊任务的行为。
- 新玩家加入后看到服务器已有进度，并核实已完成任务的领奖行为。
- 普通玩家不能通过界面或命令意外退出、切换或另建团队。
- 退出重进及服务器重启后，团队归属、进度和领奖记录保持正确。
- 原有进度保留，服主管理及任务编辑仍可使用。

## 工作量预估

此前讨论给出的粗估为：构建环境顺利时，最小可测试版约 30～60 分钟，再进行游戏内验证。这不是已核实的工期承诺，需根据接入位置、现有数据及构建情况调整。
